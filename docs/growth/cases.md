本章采用本仓库的真实改动：取消每章固定结尾问答，让知识和验证回到相关段落。它展示了内容调整为什么还需要检查组件依赖、页面状态与交互。

## 问题与目标

原章节采用统一结尾结构，阅读中容易重复，也让尚未完成的章节看起来像已有完整教学。目标是按主题组织正文，保留有价值的提醒，草稿继续明确状态；同时清除失去用途的组件与样式。

这不是简单删除一个标题：正文、草稿、首页、维护约定和共享样式都受到影响。若只全局替换词语，可能丢失独有提醒，或误删折叠步骤也在使用的动效。

## 从内容清点到依赖清理

这次改动在 commit `a8a0324` 中，可以在本仓库查看：

```bash
git show --stat a8a0324
git show a8a0324 -- docs/start/intro.md
git show a8a0324 -- docs/.vitepress/theme/styles/rich.css
```

当时对 15 篇正文去重，把独有提醒放回相关内容；67 篇草稿改为保留写作要点的清单，另有 8 篇仅有简介的草稿维持原状态。移除了闲置的结尾问答组件与首页问答卡片，同时保留 `RSteps` 仍然使用的 caret 与展开动效。

这些数字描述的是那次提交时的状态，不是本轮补齐正文后的草稿数量。查看历史时要以对应 commit 为准，避免用当前工作区解释过去的检查结果。

## 验证了什么

那次实际运行了站点构建和差异检查，核对 108 个登记路径与草稿状态，以及原 67 篇草稿的要点保留。浏览器检查了桌面与窄屏页面，并验证步骤点击、键盘展开和全部展开。

这些检查说明结构调整在所查页面与操作上成立，不能证明全站所有浏览器、原生代码或真机都通过。已有原生片段的校对状态也没有因此升级。

## 可以迁移的方法

先列内容与组件清单，再找共享依赖；删除模板前确认独有信息迁移位置；修改后分别验证内容完整性与交互。让 Codex 执行这类任务时，把「保留哪些事实」和「哪些交互不能丢」写进验收，避免只以搜索不到旧词作为完成标准。

这个案例没有企业生产指标，也没有宣称带来可量化的阅读提升。可以确认的是提交内容与实际检查，体验收益仍需要后续读者反馈。
