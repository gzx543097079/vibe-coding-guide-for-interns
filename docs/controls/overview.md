这个模块收录常用控件和动效。每个控件页都有：用途与适用场景、可以直接操作的演示（网页外框和手机外框可切换）、12 种写法的代码、「复制提示词」、方案对比和常见坑。

代码覆盖这些平台：

- 网页：HTML + CSS + JS、Vue、React
- iOS：SwiftUI、UIKit（Swift）、UIKit（Objective-C）
- Android：Jetpack Compose、View 体系（Kotlin + XML）
- 鸿蒙：ArkUI（ArkTS）
- 微信小程序：WXML + WXSS + JS
- 跨端：Flutter、React Native

## 怎么验证提示词

提示词写得够不够精确，靠实际还原来检验，不靠自己读一遍觉得清楚：

1. 按网页写法生成提示词（选项为默认的「带动画、支持深色模式、无障碍」），原样交给一个独立的 AI agent。agent 只拿到提示词文本，被要求不读本站源码，输出一个单文件 HTML。
2. 用无头 Chromium 打开它的实现和站内演示，在同样的画布尺寸下逐个状态截图对比：默认、悬停、按下、展开或选中、动画中间帧（暂停所有动画后定格在同一时刻）、禁用、深色模式。
3. 差异大的地方回头改提示词，再交给一个新的 agent 重做，最多两轮。

徽标的含义：

- **已验证**：对比过的状态都一致，只剩字体渲染、亚像素这类细小差异。
- **部分一致**：整体能还原，但有明确的差异，差异写在控件页的徽标旁边。
- **未验证**：还没做过这个流程。

局限也写在这里：

- agent 的独立性靠指令约束，不是技术隔离。
- 手机外框里的演示是网页模拟，原生平台代码没有在真机上验证。提示词的验证结果只说明「按这份提示词能在网页上还原演示」，不代表原生代码能直接编译运行。
- 截图对比只覆盖列出的状态，手势细节（拖动手感、惯性）靠人工操作检查。
