无障碍和国际化都应在组件设计时考虑。**语义、焦点和内容结构正确，后面的适配才有基础**；上线前增加几个 ARIA 属性或把文字全部翻译一遍，往往修不好早期结构问题。

## 先让基本操作可达

按钮使用按钮，链接负责导航，输入有可关联的标签。按 Tab 应能按合理顺序到达操作，焦点应可见，弹窗关闭后应回到合适的位置。错误提示需要说明问题与恢复办法，不能只靠红色边框。

| 情况 | 检查方式 |
| --- | --- |
| 键盘用户 | 不碰鼠标完成主流程 |
| 读屏用户 | 听取名称、角色、状态与错误 |
| 低视力用户 | 放大文字与页面，查看遮挡和溢出 |
| 动效敏感用户 | 开启减少动态效果，确认状态仍然清楚 |
| 触摸用户 | 真机检查触达、滚动和手势替代入口 |

自动检查可以发现部分问题，不能证明整个业务流程可用。尤其拖拽、弹窗和组合选择器，需要实际操作。

## 文案从组件里抽离

不要拼接「你好」和用户名再假定所有语言语序一致。为完整句子提供变量和复数规则，使用平台的格式化能力处理日期、数字、币种和时区。

```js
const date = new Date('2026-01-01T00:00:00Z')
console.log(new Intl.DateTimeFormat('zh-CN', {
  timeZone: 'Asia/Shanghai', dateStyle: 'medium'
}).format(date))
```

这段代码固定了显示时区；没有显式时区时，用户环境可能显示不同日期。金额的币种也不能只靠一个货币符号猜测。

## 用难一点的内容提前验证

测试长译文、中文、从右到左的文字、缺少翻译键和空值。布局尽量用逻辑方向属性与自适应宽度，不给按钮按中文长度写死尺寸。翻译结果仍需熟悉业务的使用者审校；机器翻译正确表达字面意思，也可能不符合产品语境。
