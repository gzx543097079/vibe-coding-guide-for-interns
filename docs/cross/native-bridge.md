---
title: 原生能力桥接
description: 调用相机、定位、支付等原生能力，以及插件开发。
---

桥接把跨端代码的请求转换为平台能力调用，例如相机、定位或本地文件。它是一条**带类型、权限、生命周期和错误语义的接口边界**，不只是把同名函数连起来。

## 先定义调用契约

```json
{
  "requestId": "demo-1",
  "method": "pickImage",
  "arguments": { "source": "library" }
}
```

这是自定义接口结构的示意，不是任何框架可直接执行的报文。返回结果要区分成功、用户取消、权限拒绝和系统失败；取消选择不一定是需要弹红色报错的故障。

| 需要约定的内容 | 常见遗漏 |
| --- | --- |
| 数据类型 | 大整数、空值、日期与文件句柄无法原样跨层传递 |
| 执行线程 | 耗时任务阻塞 UI，或在错误线程更新界面 |
| 生命周期 | 页面退出后仍回调，多次注册监听不释放 |
| 权限 | 前端传入路径或用户 ID 就被无条件信任 |
| 超时与重试 | 重复发起系统操作，结果无法关联 |

## 共享层不直接知道平台细节

业务代码依赖 `pickImage` 之类的稳定能力，适配层再决定使用哪个平台 API 或插件。权限检查、输入验证和路径约束应在真正执行的一侧完成；只在界面上隐藏按钮不足以保护能力。

## 用失败路径检验契约

在可控测试环境中依次覆盖允许、拒绝、取消、后台切换、页面销毁和超时。对消息通道验证来源，对返回数据做类型校验；不把完整错误堆栈或敏感路径直接展示给用户。

桥接实现、插件与框架版本需要一起维护。新增能力前先查现有插件是否满足要求，自己实现时保留契约测试和目标端运行记录；不能用浏览器里的假回调宣称原生接入已完成。
