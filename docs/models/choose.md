> 这一篇不给「哪家最好」的结论。官方页面和公开榜单都不足以回答这个问题，能做的是告诉你**每个场景该看哪几项**，以及用什么办法验证。涉及的具体型号和数字，来自前面各篇，核对于 **2026-11-13**。

## 先把场景说清楚

选模型之前，先回答四个问题：

1. **输入是什么？** 只有文字，还是有图片、音频、视频、PDF？
2. **一次要处理多长？** 输入多长，要求输出多长？
3. **要不要调用工具或输出固定格式？** 做 Agent、接口集成还是单纯问答？
4. **数据能不能出你的网络？** 能不能用海外 API，是不是必须部署在自己的机器上？

## 按场景看

### 写代码和做 Agent

该看的：

- **工具调用的限制。** 比如 Claude 的几个新型号不支持强制调用某个工具；OpenAI 的 Luna 在 Chat Completions 里只有思考设为 `none` 才支持函数调用。这些限制会直接影响你的 Agent 框架能不能原样接入。
- **思考档位和速度。** 高档位更慢、更耗 token。
- **官方的定位语。** 比如 Anthropic 把 Opus 5.5 描述为适合「长时间运行的 Agent 式编程」，Kimi 和 GLM 的文档强调代码与 Agent 能力。这是厂商自己的说法，只能作为起点。
- 网页开发类任务，Arena 有专门的 WebDev 榜，见 [怎么看榜单和热度](./signals)；它衡量的是用户对前端网页结果的偏好，不是你仓库里的任务。

### 处理长文档

- 看**最大输入**和**最大输出**，而不是只看窗口。
- 注意各家对窗口的算法：OpenAI 的最大输入小于窗口；Gemini 4 的输入与输出共用一个上限。
- 超长输入不等于每一处都读得准。用你自己的文档做一次「大海捞针」式的抽查，比相信任何宣传都可靠。

### 要读图片、音频、视频

- 先看**输入模态**这一栏。比如 Gemini 的详情页列出文本、图片、视频、音频、PDF；GPT-6 三个型号只写文本和图片；DeepSeek 的 V4 Pro 页面写明不支持图像理解，而 Flash 支持。
- 要输出语音、图片或视频，通常需要**专门的模型**：OpenAI 的 Image、Realtime，Qwen 的 omni，豆包的 Seedance、Seedream、SeedRealtime，Gemini 的 Live、TTS、Nano Banana，Grok 的 imagine 系列，都是单独列出的。

### 要私有部署或微调

- 只看**开放权重**一栏还不够，必须同时看许可。表里有 MIT、Apache-2.0，也有厂商自己的许可。
- 看参数规模和激活参数：2.4T 总参数的 MoE 模型，和 27B 的稠密模型，对硬件的要求完全不是一个量级。
- 看托管版是否也有：比如 Qwen 的「官方内置工具」只在托管版里，开放权重没有。
- OpenAI GPT-6 的三个型号，页面明确写着微调不支持。

### 成本敏感、高并发

- 各家都有定位为「高效、低延迟」的档位：OpenAI 的 Luna，Anthropic 的 Haiku 5.5，Google 的 Flash-Lite，Qwen 的 `qwen3.8-flash`，DeepSeek 的 `deepseek-flash`。
- 价格请看各家的官方定价页。这里不列，是因为它变得最快。
- 看定价页时留意有没有**按输入长度分档**、思考 token 怎么计费、缓存命中怎么计费。这几项不同厂商不一样，这里没有核对，需要你自己在官方页面确认。

### 想换模型时少改代码

- DeepSeek 的文档写明它支持 OpenAI 格式、Anthropic 格式和 Responses API，换 base URL 和模型名就能试。
- 其他厂商也有各自的兼容接口，用之前读它的文档，确认你要用的功能（工具调用、结构化输出、思考）是否在兼容层里支持。

## 一个小办法

写一个**只有 20 到 30 条的评测集**，用你真实的任务，每条写好验收标准。候选型号各跑一遍，记录通过率、延迟、token 用量。后面换型号的时候，同一套集子再跑一遍。怎么写验收标准，见 [评测与验收](/ai/evals)；怎么在质量、速度和成本之间权衡，见 [成本与效率](/ai/cost)。
