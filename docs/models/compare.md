## 读这张表时

- **上下文窗口不是越大越好用。** OpenAI 的最大输入是 922,000，加上最大输出 128,000，正好等于窗口 1,050,000；Gemini 4 的页面写的是输入和输出共用一个上限。同样写「1M」，能一次放多少输入并不一样。
- **看「最大输出」比看窗口更能预测一次能写多长。** 表里最大输出从 65,536 到 384K 不等。
- **思考档位的叫法各家不同。** 同样是 `max`，在不同厂商那里的含义和耗时不能直接比较。
- **「开放权重」要同时看许可。** MIT 和 Apache-2.0 是通用的许可；`Kimi K3.1 Pro License`、`qwen-community-1.0` 这类是厂商自己的许可，需要读全文，见 [大陆可用性、备案与许可](./compliance)。
- **同一系列的不同尺寸差别很大。** 比如 Qwen 的百炼 API 型号是 1M 上下文，开放权重的 27B 是原生 262,144。

## 想自己对比时

最可靠的办法是用你自己的任务做一个小评测集：同一批输入，用不同型号各跑一遍，对比结果、延迟和 token 用量。做法见 [评测与验收](/ai/evals)。表格只能帮你缩小候选范围。
