这一组笔记介绍美国和中国大陆常用的大模型。先说明两件事：**读什么**，以及**这里的内容从哪来、能信到什么程度**。

## 先看哪几项

厂商的介绍页常常把一堆指标摆在一起。对写代码的人来说，下面几项最常影响结果：

<RPoints>
<RPoint icon="file" title="上下文窗口与输出上限">一次能放进去多少内容，一次最多能写出多少。两个数不是一回事：窗口大不代表一次能写很长。</RPoint>
<RPoint icon="path" title="输入、输出模态">能不能读图片、音频、视频或 PDF，输出是只有文字，还是也能出图、出语音。</RPoint>
<RPoint icon="chat" title="思考（推理）档位">多数厂商有「想多久」的档位，档位越高越慢、越耗 token。有的型号思考是常开的，关不掉。</RPoint>
<RPoint icon="gear" title="工具调用与结构化输出">能不能按你给的格式调函数、输出固定结构的 JSON。做 Agent 和接口集成时，这两项比「聪明程度」更先卡住人。</RPoint>
<RPoint icon="license" title="是否开放权重，以及许可">能不能下载到自己的机器上跑，许可允许你做什么。「开源」这个词不够用，要看许可名称。</RPoint>
<RPoint icon="flag" title="哪里能用">官方 API 对哪些国家和地区开放。这一项会直接决定你能不能接入，后面有专门一篇。</RPoint>
</RPoints>

## 这一组笔记怎么取材

模型更新很快，所以这里的写法和别的章节不一样：

- **只认官方页面。** 每一篇的数据来自厂商自己的文档、模型页或官方模型卡，文末列出出处。第三方博客和新闻不作为依据。
- **标核对日期。** 本组笔记的数据核对于 **2026-11-13**。过了这个日期，型号、上下文和状态都可能变。
- **页面没写的就写「页面未写」。** 不用记忆或推测去补。比如某个模型页没有写发布日期，这里就不写。
- **不写价格和基准分数。** 这两类数字变得最快，也最容易被断章取义。想比较，请去官方定价页。
- **不替任何一家背书。** 这里介绍的是官方写了什么，不是「哪家最好」。

<RCompare bad-title="容易踩的坑" good-title="更稳的做法">
<template #bad>

- 看到「上下文 1M」就一次塞满，不看输出上限和延迟。
- 把型号名当成固定的：「我用的 GPT」「我用的 Claude」，其实每次说的不是同一个模型。
- 直接复制别人文章里的模型 ID，没去官方页确认。

- 窗口、输出上限、思考档位三个数一起看，再用自己的任务试。
- 记下完整的模型 ID 和日期，以后出问题能对上是哪一版。
- 模型 ID、参数名都回官方页核对；页面之间写法不一致时，以对应的模型页为准。

</template>

## 「比较火」是怎么定的

这一组笔记选了哪些厂商，参考了两类公开信号，都带日期，放在 [怎么看榜单和热度](./signals) 一篇里：

- OpenRouter 的调用量排名：衡量经过这个平台的 token 流量。
- Arena 的文本榜和网页开发榜：衡量用户盲测投票的偏好。

两者都有盲区：国内平台直接提供的服务，大部分不会出现在这两个榜上。所以选择国内厂商时，同时参考了它们各自官方文档是否齐全、近期是否仍在更新。榜单只是线索，不是结论。
