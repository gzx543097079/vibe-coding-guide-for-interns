编码 Agent 通常是**一个让模型循环调用工具的程序**：模型看当前上下文，决定下一步；需要动手时输出一个工具调用请求；程序执行，把结果放回上下文；模型再看、再决定。它可以回复后结束，也会因为预算、超时、错误或用户中断而停止。任务清楚、验收明确，更容易判断什么时候该继续、什么时候该停。

## 四个阶段，各自容易出什么问题

<RPoints>
<RPoint icon="eye" title="观察">模型只看得到上下文里的东西：你的话、规则文件、之前读到的文件和命令输出。你没提供、它也没去读的，它就不知道。</RPoint>
<RPoint icon="bulb" title="思考">根据上下文决定下一步。信息不够时，它可能去读文件，也可能直接猜。猜的那一步最容易出错。</RPoint>
<RPoint icon="terminal" title="调用工具">读文件、搜代码、改文件、跑命令。真正执行的是 Agent 程序，不是模型；执行前要不要问你，取决于权限设置。</RPoint>
<RPoint icon="file" title="结果回传">命令输出、文件内容原样进入上下文，下一圈模型就基于这些继续。输出越长，上下文涨得越快。</RPoint>
</RPoints>

## 循环什么时候停

在 Codex 中，重点看工具调用记录、命令输出和最终验收结果。要理解 API 侧的循环，可看 OpenAI Responses API：检查 `output` 是否还有 `function_call`，有就执行并回传；没有时继续检查响应 `status` 和错误，再判断能否结束。详见 [工具调用](./tool-use) 与 [官方函数调用文档](https://developers.openai.com/api/docs/guides/function-calling)。API 响应完成，只代表那次生成结束，不代表整个任务已经完成。

所以「它说做完了」只是模型的判断。它可能在测试还没跑、或者跑失败了的情况下就宣布完成。

<RCompare bad-title="让它自己判断什么时候算完" good-title="把「做完」定义成能检查的条件">
<template #bad>

> 帮我把这个 bug 修好。

它改了一处、觉得应该没问题，就结束了。测试跑没跑、跑没跑过，你得自己去翻。

</template>
<template #good>

> 修复 `tests/sum.test.ts` 里失败的用例。完成的标准：`npm test` 全部通过，并把最后一次的测试输出贴出来。只改 `src/` 下的文件，不改测试。

有了能检查的标准，你就能对照输出验收。若权限、环境或预算阻止继续，Agent 应说明阻塞原因和未完成项。

</template>
</RCompare>

## 在循环里保持控制

<RSteps>
<RStep title="先让它只读" note="计划模式下只看不改" open>

在 Codex CLI 里用 `/plan` 讨论实现方案；要限制本地命令写入，可另外选择只读沙箱。计划模式是协作方式，沙箱才是执行边界，两者不要混为一谈。

</RStep>
<RStep title="看清每一次工具调用" note="尤其是命令">

是否询问取决于工具、权限模式和已经批准的规则。需要批准时，看清命令本身：它要删什么、装什么、推到哪里。已经自动放行的操作也要能回查记录，见 [权限与安全](./permissions)。

</RStep>
<RStep title="绕圈了就打断" note="同一个错误改三次还没好">

如果它反复改同一处、测试反复失败，通常是缺信息或方向错了。打断它，补充上下文或换个思路，比让它继续烧 token 有用。

</RStep>
<RStep title="最后自己验收" note="不信总结，看 diff 和输出">

循环结束后，自己看 `git diff`、自己跑一遍测试。它的总结可能遗漏改动，也可能夸大结果。

</RStep>
</RSteps>

## 动手前的三问

<RAsk>
<template #know>

- Agent 是「模型 + 执行工具的程序」，模型只负责决定下一步。
- 每一圈的工具结果都会进入上下文，长任务会把窗口占满。
- 循环可能正常结束，也可能因限额、错误或中断而停止，都要对照验收标准检查。

</template>
<template #verify>

- 给出可检查的完成标准，比如某条命令全部通过。
- 循环结束后自己运行测试，对比它贴出的输出。
- 用 `git diff` 看实际改了哪些文件，是否都在约定范围内。

</template>
<template #pitfall>

- 信息不够时不去读文件，凭猜测修改。
- 测试失败后改测试本身，让测试「通过」。
- 没运行验证命令就宣布完成，或者无视失败的输出。

</template>
</RAsk>
