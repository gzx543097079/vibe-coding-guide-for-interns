把代码交给 AI 处理之前，先确认**数据属于谁、发到哪里、为什么可以发送、需要保留什么记录**。工具能读到文件，不等于组织已经允许把内容发送到外部模型或连接器。

## 先画出数据流

一次 Codex 任务可能涉及本地文件、模型服务、MCP Server、浏览器和日志系统。分别列出输入、输出、账号权限、保存位置和保留时间。只检查模型服务的条款，不能覆盖第三方工具的处理方式。

| 数据 | 日常处理方式 |
| --- | --- |
| 密钥、令牌、私钥 | 不放进提示词、仓库或截图；意外暴露后按团队流程撤销与轮换 |
| 用户与业务记录 | 优先用脱敏样本，确认用途和发送范围 |
| 内部源码 | 先核对组织允许的产品、账号和数据政策 |
| 第三方代码 | 保留来源、许可证与必要声明，核对使用条件 |

这些是工程中的处理步骤，不替代组织的法律、安全或隐私评审。涉及合同、受监管数据和跨境要求时，由相应负责人确认适用规则。

## 不把「不用来训练」等同于「没有存储」

训练用途、滥用监测日志、应用状态、数据驻留和删除政策是不同问题；同一厂商的不同产品、端点与账号配置也可能不同。根据当前官方数据说明和组织合同逐项核对，不沿用聊天助手对条款的口头概括。

## 依赖和生成代码都要看来源

新增依赖时检查维护方、版本、许可证及传递依赖。模型写出的代码没有自动免除来源和使用义务；接近第三方实现的大段代码，更需要核对来源与团队要求。不要把「包能安装」当作许可证可用的证明。

## 审计记录留下必要证据

记录任务目的、批准范围、实际版本、变更和检查结果；敏感输入本身不应因为「留痕」而被复制进另一个日志系统。意外外发时先停止相关动作并按团队流程报告，保留最小证据，不让 Agent 擅自清理记录或继续尝试。
