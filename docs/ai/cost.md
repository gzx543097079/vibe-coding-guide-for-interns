---
title: 成本与效率
description: token 用量、模型选择与等待时间之间的权衡。
---

衡量效率要看**交付一个正确、可维护结果的总成本**：模型使用、等待、验证和返工都算。一次生成便宜却需要反复重做，不一定比一次更仔细的实现节省。

## 先记录，再选择模型

记录任务类型、输入输出用量、等待时间、工具执行耗时和人工修改。API 的 token 费用、订阅额度和 Codex 的产品限制不是同一口径；模型单价和可用额度应查询当前账号与官方价格页，不在项目文档里写死。

| 工作 | 主要成本来源 | 先尝试的改进 |
| --- | --- | --- |
| 解释局部代码 | 读入太多无关文件 | 限定入口，再按调用链扩展 |
| 修复复杂问题 | 缺复现导致反复猜测 | 补充日志和失败测试 |
| 批量机械改动 | 重复任务与审查量 | 写清转换规则，抽查异常文件 |
| 多 Agent 协作 | 重复上下文和整合 | 只拆真正独立的工作 |

## 缩短无效循环

一个错误连续出现时，先检查假设有没有变化。反复换一句「再试试」不会补足缺失的版本、数据或业务规则。让 Codex 报告已经排除的原因和下一步要验证的假设，失败之后更容易判断是否值得继续。

## 比较方案时固定任务和验收

不要只比较第一条回复速度。用相同任务、环境和验收条件记录从开始到通过检查的时间；保留失败和重试，不把它们从统计里删掉。少量任务只适合发现问题，不能据此宣称某模型普遍更好。

```text
先完成最小可运行改动并验证，不扩大重构范围。
若同一假设验证失败两次，停止重复尝试，列出新证据和替代假设。
总结实际运行的命令、耗时来源和仍未解决的问题。
```

复杂推理、轻量解释和机械转换可以采用不同的工作安排，但模型选择仍须以当前产品能力和真实验收结果为依据。
