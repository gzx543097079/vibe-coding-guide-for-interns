## 计划覆盖

- 不盲信 AI 输出：每一行都要能解释
- 审查 diff 的顺序：正确性、安全、风格
- 识别幻觉：不存在的 API、参数与配置项
- 自审清单：提交前自己先过一遍

## 三问

答得上这三个问题，再把这个方向的任务交给 AI。下面是计划展开的要点。

### 必须先懂什么

- 改动的目的与影响范围
- 项目中相关代码的现有写法

### 怎么验证

- 对照官方文档确认 API 存在
- 运行测试并手动走一遍主流程

### AI 常错在哪

- 编造看似合理的 API
- 在你没要求的地方顺手修改代码
