移动端性能最终要回到目标设备。模拟器适合调功能与布局，不能据此判断真机的帧耗时、内存压力、温度和电量。

## 固定测试条件

选择接近用户分布的设备档位，记录系统、应用版本、发布构建方式、数据规模与网络。至少区分冷启动、热启动、长列表滚动和连续导航。设备充电、发热、后台任务和电量模式会改变结果，比较前后要保持条件接近。

先测完整旅程，再拆到主线程、渲染、I/O 和网络。平均帧率可能掩盖少量明显卡顿；内存峰值与反复进出页面后的增长，也比某一刻的占用更有解释力。

## 原生与跨端各看哪里

iOS 可借助 Xcode 和 Instruments，Android 可用 Android Studio 的性能工具与系统追踪。工具和分析方式要匹配实际构建类型，调试器本身也可能影响数据。

跨端应用还需区分业务运行时、原生 UI 线程和桥接调用。一次滚动卡顿，可能来自图片解码，也可能来自高频事件跨边界传输。不要把所有问题都归因于框架；先保留调用频率、负载大小和各线程时间线。

## 用一个场景检查资源释放

固定一份本地测试数据，连续进入和退出详情页。观察页面销毁后计时器、订阅、图片缓存和原生资源是否释放，再比较多轮操作后的趋势。缓存保留可能合理，持续增长也不必然都是泄漏，需要结合对象引用和平台回收机制判断。

优化图片规格、批量桥接或列表复用后，重新检查取消操作、返回栈、状态恢复和无障碍。把计算移到后台线程也要考虑线程切换和结果过期，不是改成异步就结束。

向 Codex 提供脱敏的 trace、设备条件和可复现步骤，让它提出具体实验。本指南中的原生片段没有完成编译或真机性能验证；网页中的手机演示只说明交互思路，不能作为原生性能证据。
