# 提示词还原验证

「组件演示」里每个效果都配了一份提示词。这里的脚本用来确认：只凭提示词，能不能做出和站内演示一样的东西。

目前覆盖「App 里的效果」四项：滑动回复、长按表情回应、快拍分段进度、图片放大查看。

## 目录

- `snapshots/`：验证通过时的提示词原文（网页写法、默认选项、iPhone 外框、iOS 色值表）。
- `fixtures/`：独立 agent 只凭提示词写出的单文件实现。它们没有看过站内演示的源码。
- `cases/`：每个效果的操作脚本，对站内演示和独立实现执行同样的操作并比对。
- `helpers.js`：操作脚本共用的工具（模拟指针事件、取元素位置和样式、比对）。

## 两个检查

```bash
npm run check:prompts
```

比较当前生成的提示词和 `snapshots/` 里的版本。不需要浏览器，CI 里每次都跑。提示词被改动时会失败，提醒你重新验证。

```bash
npm run build
```

```bash
npm run verify:prompts
```

在无头 Chrome 里打开站内演示，同时用 iframe 加载 `fixtures/` 里的独立实现，逐状态比对元素的位置、尺寸、颜色、圆角和透明度。输出里竖线左边是站内演示，右边是独立实现。只跑某一项时把 id 写在后面，例如 `npm run verify:prompts -- zoom`。

这一步需要本机装有 Chrome，结果要人来读，CI 里不跑。

## 读结果时要知道的

- `SAME(n)` 表示 n 个元素完全一致。列出 `A` / `B` 两行时是有差异的元素。
- 「焦点」一栏只有一边有值是正常的：两边在同一个页面里，后获得焦点的会抢走前一个的焦点。
- 滑动回复的「键盘回车回复」一栏右边是 `false` 也是正常的：脚本用的是程序触发的点击，独立实现监听的是键盘事件。
- 按钮和图标的字号差 1px（13px 和 14px）来自继承，不影响外观。
- 动画只在固定时刻取了中间帧，没有逐帧比对。

## 提示词改了以后

1. 把新的提示词原文交给一个没看过源码的 agent，让它重写对应的 `fixtures/<id>.html`。页面要求：画布是左上角的 `<div id="canvas">`，248×442，URL 带 `?dark` 时用深色值。
2. 运行 `npm run verify:prompts -- <id>`，逐行看结果。
3. 一致后运行 `node scripts/verify-prompts/check-snapshots.mjs --update`，并在 `controlPrompts.ts` 的验证记录里写上日期、轮数和说明。

## 没覆盖的

- 另外 17 个组件的验证是更早做的，当时的提示词原文和独立实现没有保存，所以不在这里。
- 只验证了网页写法。SwiftUI、Compose 等原生技术栈的提示词没有验证。
- 手势是脚本模拟的指针事件，没有在真机上用触摸操作过。
