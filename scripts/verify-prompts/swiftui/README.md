# SwiftUI 版提示词验证

上级目录的验证只针对网页写法。这里把四个效果的提示词选成 SwiftUI 技术栈，交给没看过源码的 agent 各写一个视图，编译后装进 iOS 模拟器，用真实触摸注入逐项操作。

## 做法

1. `node scripts/verify-prompts/swiftui/export-prompts.mjs` 导出四份提示词原文（SwiftUI、默认选项、iPhone 画布、iOS 色值表）。
2. 每个效果一个独立 agent，只读对应的提示词，写出 `App/<名字>Demo.swift`，并自己做类型检查。
3. `App/VerifyApp.swift` 是宿主：把画布固定放在屏幕 (77, 220)，尺寸 248×442 pt，底部可切换效果和深浅色。
4. `xcodegen` 生成工程，`xcodebuild` 编译（iPhone 18 Pro 模拟器，iOS 27.2，Xcode 27.2），`simctl` 装机运行。
5. 用模拟器的触摸注入（点按、拖动、按住）操作，截图在 `screenshots/`。

重跑：`cd scripts/verify-prompts/swiftui && xcodegen`，用 Xcode 打开 `PromptVerify.xcodeproj` 运行即可。

## 结果

编译：四个视图一次通过，无警告。

| 效果 | 操作过的项 | 结果 |
|---|---|---|
| 滑动回复 | 向左拖、过阈值、松手、发送、短距离拖动 | 一致。气泡跟手，箭头渐显，过阈值变强调色，松手后引用条出现，发送后新气泡带引用；短距离松手不出现引用条 |
| 快拍分段进度 | 自动推进、点右侧、按住 | 一致。分段进度推进，点右侧切到下一条，按住时顶部区域隐藏 |
| 图片放大查看 | 点缩略图、全屏、向下拖动、松手 | 一致。放大到全屏，拖动时缩小、遮罩变淡并透出网格，松手关闭回到网格 |
| 长按表情回应 | 长按、选表情、短按 | **有一处不一致**：长按打开的表情条盖在被长按的气泡上，而不是在它上方 8pt。选表情后的徽章、短按不打开都正常 |

不一致的这一处，提示词写得很明确（「底边距气泡顶部 8px」），所以更可能是实现的问题。agent 自己也提到遮罩和表情条用零高度容器溢出实现，不确定布局。这一项没有修，也没有因此改提示词。

## 没验证的

- 点击是单次注入的，没有逐帧比对动画；动画只在截图时刻看了中间状态。
- 没有用真机。模拟器的触摸注入不等同于手指操作。
- 键盘、读屏（VoiceOver）、外接键盘的行为都没有测，各 agent 汇报里提到的不确定项（焦点环、`onKeyPress`、`accessibilityAction` 等）保持不确定。
- 深色模式没有逐个截图。
- 表情回应的右键打开在 iOS 上没有对应，agent 没有实现，提示词也没有说明原生端怎么替代。
- 打开软键盘时宿主的整体布局会被顶上去，是宿主 `ZStack` 的问题，不是视图的问题。

## 提示词里在原生端行不通的写法

各 agent 的汇报里重复出现的几类，改提示词时可以参考：

- 写成网页 API（Pointer Events、`requestAnimationFrame`、`touch-action`）的句子，原生端要自己换成手势和显示链接。
- 「行高 1.45」「悬停」「光标 grab」在 SwiftUI 里没有对应。
- `oklch(...)` 颜色没有 sRGB 兜底值，两个 agent 都手写了转换。
- 无障碍部分按网页写（`aria-label`、`aria-live`、「按回车」），原生端要拆成 label、hint 和通知。
- 缓动令牌里的「退出 ease-in」和动画节写的「280ms ease」互相矛盾，两个 agent 都发现了。

这些没有改进提示词里，因为提示词当前的验证对象是网页写法，改了会触发重新验证。
